# 第三步：实现请求转发
找到路由后，把请求转发到目标服务，并将后端的响应返回给前端。先支持 GET、POST，再补充其他 HTTP 方法；也要逐步处理查询参数、请求体、常用请求头和响应状态码。
验收：准备两个简单的后端服务，通过不同网关路径访问，能看出请求分别到达了不同服务。
# 第四步：加入前置过滤器
定义统一的过滤器接口，例如 pre 阶段在路由转发前执行。先实现日志过滤器，再实现一个简单的请求校验或令牌校验过滤器。
验收：请求日志能显示；缺少必要令牌时，网关直接拒绝请求，不调用后端。
# 第六步：加入后置和异常过滤器
后置过滤器在后端响应返回后执行，例如记录耗时或添加响应头。异常处理则负责处理路由未找到、后端不可用和转发失败等情况。
验收：正常请求会执行前置和后置过滤器；后端停机时，网关仍能返回格式统一的错误响应。
# 第七步：整理配置和补充测试
把路由匹配、转发和过滤器分别放到独立类中，并用单元测试或集成测试覆盖匹配成功、无匹配路由、过滤器拦截和后端异常。
可以按这个结构组织：
config/       路由配置
route/        路由匹配
proxy/        请求转发
filter/       前置、后置、异常过滤器
controller/   网关入口
exception/    统一错误处理
